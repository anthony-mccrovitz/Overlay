# Shadow Picks & Strategy CLV — Plan

**Status:** proposed → building Phase 1
**Goal:** Measure CLV (and W/L) for *strategies we don't bet with real money*, so we can
discover which markets/edges actually beat the close before committing stakes or building
a product. This is the keystone of the "prove edge before product" thesis.

---

## 1. Why this exists

We now capture closing lines for every market (spread/ML/total + props, all active sports).
But **CLV needs two halves**: our line at *bet time* (opening) and the *close*. For markets we
don't model or bet, we have the close but no opening — so no CLV.

A **shadow pick** supplies the missing half: a pick generated by a model *or a research rule*,
logged but **not bet** (`card_pick=False`, `stake=0`), snapshotted at open, then scored against
the close. It costs nothing to "place" and turns any edge hypothesis into a measurable CLV track.

## 2. Key decision — reuse, don't rebuild

The codebase already has the shadow primitive:
- Picks with `card_pick=False` already live in `picks.json`, already get snapshotted by
  `snapshot_from_pnl()`, already get graded, and already show in the shadow record
  (`chef.py record` shadow view). Models already log non-card picks this way.

So we **do not** build a parallel store. A shadow strategy pick is just a `picks.json` row with
`card_pick=False`, `stake=0`, and a new **`strategy`** tag. Everything downstream already works.

The only genuinely missing pieces:
1. A **`strategy`** field on picks + snapshots (so we can slice CLV by strategy, not just market).
2. **Non-model strategies** (research rules like favorite-longshot) — a small registry + logger.
3. A **by-strategy CLV report**.

## 3. Schema changes (additive, backward-compatible)

### `picks.json` row — add one field
```
strategy   str|null   which strategy produced this pick. null = a normal model/card pick.
                       e.g. "fav_longshot". card picks stay null so nothing reclassifies.
```
- Added to `CANONICAL_FIELDS` and emitted by `normalize_pick()` (defaults to null).
- **pick_id namespacing:** shadow picks set `pick_id = f"{strategy}__{base_pick_id}"` so two
  strategies that pick the same team/market/direction don't collide or dedup into one.

### `snapshots.json` record — add one field + finer dedup key
```
strategy   str|null   copied from the pick at snapshot time.
```
- Snapshot dedup key changes from `(date, team, market)` → `(date, team, market, strategy)`.
  Existing rows have `strategy=None`, so their grouping is unchanged (safe). Shadow picks get
  their own snapshot even when a card pick exists for the same team/market.

No change to closing archives — they already carry every market.

## 4. Data flow

```
  (morning, lines soft)                     (≈tipoff)              (next day)
  chef.py strategies  ──►  picks.json  ──►  capture_closing  ──►  chef.py clv --refresh  ──►  report
   run registry            card_pick=F       (already live)        backfill→upgrade→            chef.py strategies
   each strategy →         stake=0,                                compute_clv scores            --report
   shadow picks            strategy=tag                            every snapshot by             (CLV by strategy)
        │                       │                                  market (already)                    ▲
        └── snapshot_from_pnl() ┘  writes opening snapshot ────────────────────────────────────────────┘
        └── grade.py grades W/L (already, for non-card picks too)
```

Nothing new in the daily pipeline except one morning call to log shadow picks; the rest
(snapshot → capture → compute_clv → grade → report) is existing machinery.

## 5. Strategy registry

A strategy is a pure function `fn(odds_df, sport) -> list[pick dict]`. Registered by name.

**Phase 1 (ship now) — zero-model benchmark:**
- **`fav_longshot`** — favorite-longshot bias (most-replicated finding in the literature:
  favorites are underpriced, longshots overpriced). Rule: for each game, log a moneyline shadow
  pick on the **favorite** (side with the higher implied probability), at the best available price.
  Needs only the `h2h` odds we already fetch. One pick per game, every active sport.

**Phase 2 (next) — plug into same registry, no infra changes:**
- `dog_ml` — the underdog side, as the explicit control group to quantify the bias size.
- `model_*` — shadow the existing model fair lines on markets we don't post (props especially —
  the documented soft market). Reads model output, logs its line as a shadow pick.
- Additional documented edges (contrarian/“fade” once we have bet% data, totals biases, etc.).

Adding a strategy = write one function + register it. No schema/flow changes.

## 6. Reporting

- `get_clv_by_strategy()` / `print_clv_by_strategy()` in `clv_tracker.py` — mirrors the existing
  `get_clv_by_market()` but buckets by the `strategy` tag: per strategy → picks, scored,
  avg CLV (prob or line), beat-close %.
- Surfaced via `chef.py strategies --report` and folded into `chef.py clv`.

## 7. CLI

`shadow` is taken (hot/cold A/B filter analysis), so the new command is **`chef.py strategies`**:
- `chef.py strategies` — log today's shadow picks for active sports + show by-strategy CLV.
- `chef.py strategies --report` — report only, no logging.
- `chef.py strategies --date YYYYMMDD` — log/report for a specific slate.
- Wire a morning cron/Action step (after picks generate, when lines are soft).

## 8. Honest constraints

- **Volume = time.** Trustworthy CLV needs hundreds-to-~1000 picks per strategy. At a few games
  a day this is weeks-to-months per strategy. The job is to let it accumulate, not to rush it.
- **Measure cheap, model expensive.** Use rules to *measure* many markets; only build a real
  predictive model once a market's rough CLV justifies it.
- **Keep scope tight** — a few strategies so samples fill and the report stays legible.
- **Promotion gate:** a strategy graduates shadow → real (`card_pick=True`) only on positive CLV
  over a real sample **that persists out-of-sample** (guards against multiple-comparisons luck).
